# План перехода на новую систему доменных адресов

## Цель

Полностью вывести `imagetransformation.ru` из использования и распределить публичные статические страницы по отдельным тематическим доменам.

Один экземпляр приложения и один контейнер продолжают обслуживать все домены. Traefik принимает запросы для шести доменов, а Fastify выбирает страницу по заголовку `Host`. Основной домен `portret-iz-foto-ai.ru` обслуживает приложение, API и служебные страницы.

> В исходной постановке строка `semeynoe-foto-ai.ruuluchshit-gruppovoe-foto.html` интерпретирована как две склеенные строки: `semeynoe-foto-ai.ru` относится к странице живописного семейного портрета, а `uluchshit-gruppovoe-foto.html` — к `gruppovoe-foto.ru`.

## Целевая схема адресов

| Исходный файл | Новый публичный адрес |
|---|---|
| `static/site/index.html` | `https://portret-iz-foto-ai.ru/` |
| `static/site/raskrasit-cherno-beloe-foto.html` | `https://raskrasitfoto-ai.ru/` |
| `static/site/restavraciya-staryh-foto.html` | `https://restavraciyafoto-ai.ru/` |
| `static/site/zhivopisnyy-portret-kak-podarok-na-yubiley.html` | `https://semeynoe-foto-ai.ru/` |
| `static/site/uluchshit-gruppovoe-foto.html` | `https://gruppovoe-foto.ru/` |
| `static/site/delovoy-portret-iz-foto.html` | `https://delovoy-portret-ai.ru/` |
| SPA из `frontend-dist/` | `https://portret-iz-foto-ai.ru/app/` |

Служебные адреса размещаются только на основном домене:

- `https://portret-iz-foto-ai.ru/app/`
- `https://portret-iz-foto-ai.ru/api/...`
- `https://portret-iz-foto-ai.ru/uploads/...`
- `https://portret-iz-foto-ai.ru/oferta`
- `https://portret-iz-foto-ai.ru/privacy`
- `https://portret-iz-foto-ai.ru/o-servise`
- `https://portret-iz-foto-ai.ru/kak-polzovatsya`
- `https://portret-iz-foto-ai.ru/admin`
- `https://portret-iz-foto-ai.ru/pay_yookassa`
- `https://portret-iz-foto-ai.ru/yookassa/webhook`

## 1. Перестроить маршрутизацию приложения

Текущая маршрутизация в `src/webServer.ts` выбирает публичную страницу только по URL-пути. Ее необходимо заменить на карту `домен -> файл`:

```text
portret-iz-foto-ai.ru  + / -> site/index.html
raskrasitfoto-ai.ru    + / -> site/raskrasit-cherno-beloe-foto.html
restavraciyafoto-ai.ru + / -> site/restavraciya-staryh-foto.html
semeynoe-foto-ai.ru    + / -> site/zhivopisnyy-portret-kak-podarok-na-yubiley.html
gruppovoe-foto.ru      + / -> site/uluchshit-gruppovoe-foto.html
delovoy-portret-ai.ru  + / -> site/delovoy-portret-iz-foto.html
```

Необходимые правила:

- [ ] `/` каждого тематического домена отдает только назначенную ему страницу.
- [ ] `/app/`, `/api/`, `/uploads/`, оплата, админка и юридические страницы доступны только на `portret-iz-foto-ai.ru`.
- [ ] Запрос `/app` или `/app/` на тематическом домене получает `308` на `https://portret-iz-foto-ai.ru/app/`.
- [ ] Неизвестный домен получает `421 Misdirected Request` или `404`, а не главную страницу.
- [ ] Варианты с `www` либо не создаются, либо всегда перенаправляются на домен без `www`.
- [ ] Прямая публикация `/site/*.html` прекращается, чтобы не создавать дубли страниц.
- [ ] Общая раздача `static/` от корня заменяется на явно разрешенные файлы и каталоги либо ограничивается проверкой домена.

## 2. Исправить ссылки и ресурсы статических страниц

Сейчас страницы используют относительные ссылки `/app/`, `/site/site.css`, `/o-servise` и `/app/images/...`. После разделения доменов часть таких ссылок будет вести на неправильный хост.

- [ ] Все CTA на приложение заменить на абсолютные ссылки `https://portret-iz-foto-ai.ru/app/?example=...`.
- [ ] Ссылки между тематическими страницами направить на корни соответствующих доменов.
- [ ] Ссылки на инструкцию, страницу сервиса, оферту и политику направить на основной домен.
- [ ] Определить единый способ раздачи CSS, favicon и изображений: обслуживать их на каждом домене либо использовать абсолютные URL основного домена.
- [ ] Ссылки на демонстрационные изображения `/app/images/...` сделать абсолютными либо гарантированно раздавать эти ресурсы на всех доменах.
- [ ] Добавить к CTA источник перехода, например `utm_source=gruppovoe-foto.ru&utm_medium=landing`.
- [ ] Не менять Vite `base: "/app/"`: он соответствует целевой структуре.

## 3. Обновить конфигурацию приложения

В `.env` установить:

```env
WEBAPP_URL=https://portret-iz-foto-ai.ru
```

Текущее значение по умолчанию в `src/config.ts` также заменить.

Эта настройка используется для:

- ссылок подтверждения email;
- публичных URL загруженных и сгенерированных файлов;
- ссылок Telegram-бота на оплату, админку и оферту;
- платежных возвратных URL.

Дополнительное улучшение:

- [ ] Переименовать `WEBAPP_URL` в более точное `APP_ORIGIN` либо сохранить обратную совместимость на время перехода.
- [ ] Хранить список тематических доменов отдельно от origin приложения.
- [ ] Добавить централизованный конфигурационный объект доменов, чтобы адреса не дублировались по HTML и TypeScript-файлам.

## 4. Настроить DNS, Traefik и TLS

Для всех шести доменов:

- [ ] Создать `A`-записи на IP текущего сервера.
- [ ] Добавлять `AAAA` только при реально настроенном IPv6.
- [ ] Получить TLS-сертификаты через действующий Traefik cert resolver.
- [ ] Проверить перенаправление HTTP на HTTPS.
- [ ] Не создавать `www` или настроить постоянный редирект с `www` на домен без `www`.

В `docker-compose.yml` заменить router старого домена:

- [ ] Создать router основного домена `portret-iz-foto-ai.ru`.
- [ ] Создать router для пяти тематических доменов.
- [ ] Оба router направить в существующий Fastify-контейнер на порт `8080`.
- [ ] После полной проверки удалить `imagetransformation.ru` из router, DNS и сертификатов.

Поднимать отдельный контейнер для каждого домена не требуется.

## 5. Перенести SEO-настройки

Для каждой статической страницы:

- [ ] Установить self-canonical на корень собственного домена.
- [ ] Обновить URL в JSON-LD, breadcrumbs, `ProfessionalService`, `Offer` и `HowTo`.
- [ ] Добавить или обновить `og:url`, `og:title`, `og:description` и изображение.
- [ ] Не устанавливать canonical тематических страниц на основной домен.
- [ ] Проверить уникальность заголовка, описания и содержимого каждого лендинга.

Служебные файлы должны зависеть от домена:

- [ ] На каждом тематическом домене отдавать собственный `/robots.txt`.
- [ ] На каждом тематическом домене отдавать `/sitemap.xml` с единственным публичным URL `/`.
- [ ] На основном домене включить в sitemap главную и выбранные информационные страницы.
- [ ] Закрыть от индексации `/app/`, `/api/`, `/uploads/`, `/admin` и платежные страницы.
- [ ] Удалить `imagetransformation.ru` из `static/robots.txt`, `static/sitemap.xml` и всех HTML-файлов.
- [ ] Добавить все шесть сайтов в Яндекс Вебмастер и Google Search Console.
- [ ] Подтвердить владение каждым доменом и отправить соответствующие sitemap.

### SEO-последствие отказа от старого домена

Поскольку `imagetransformation.ru` не будет использоваться даже для `301`-редиректов, поисковый вес старых URL не будет явно перенесен. Новые домены будут индексироваться практически как новые сайты. Это принятое ограничение целевой схемы, а не техническая ошибка миграции.

## 6. Перенести аналитику и атрибуцию

Сейчас на статических страницах используется один счетчик Яндекс Метрики `111270321`.

- [ ] Выбрать один вариант: добавить все домены в существующий счетчик или создать отдельный счетчик для каждого лендинга.
- [ ] Передавать исходный домен через UTM при переходе в приложение.
- [ ] Сохранять первый `landing_domain`/`utm_source` при регистрации или первом открытии приложения.
- [ ] Проверить, что переходы между доменами не теряются и не считаются прямым трафиком.
- [ ] Настроить цели регистрации, загрузки фотографии, запуска генерации и оплаты.

## 7. Обновить почту и юридические документы

Адрес `hello@imagetransformation.ru` нельзя оставлять, если старый домен полностью выводится из использования.

- [ ] Создать новый адрес, рекомендуемый вариант: `hello@portret-iz-foto-ai.ru`.
- [ ] Настроить MX, SPF, DKIM и DMARC.
- [ ] Обновить `SMTP_FROM`.
- [ ] Заменить email в `static/oferta.html`, `static/privacy.html`, `static/site/o-servise.html`, `frontend/index.html` и других найденных местах.
- [ ] Заменить адрес сайта и адрес актуальной версии документа в оферте и политике.
- [ ] Проверить BCC и отправителя в `src/email.ts`.
- [ ] Отправить тестовое письмо подтверждения и проверить доставку и ссылки.

## 10. Проверки перед отключением старого домена

### Маршрутизация

- [ ] Корень каждого домена возвращает `200` и правильную страницу.
- [ ] Тематические страницы недоступны под чужими доменами.
- [ ] Неизвестные пути возвращают ожидаемый `404`, а не случайную страницу.
- [ ] `/app/` тематических доменов перенаправляется на основной домен.
- [ ] `http://` перенаправляется на `https://`.
- [ ] Сертификаты всех доменов валидны.

### Приложение

- [ ] `https://portret-iz-foto-ai.ru/app/` и его статические ресурсы загружаются без ошибок.
- [ ] Регистрация и вход работают.
- [ ] Письмо подтверждения ведет на новый основной домен и затем в `/app/`.
- [ ] Загрузка фотографии работает.
- [ ] Генерация возвращает доступный публичный URL нового домена.
- [ ] История, баланс и оплата работают.
- [ ] Webhook ЮKassa принимается и платеж зачисляется.
- [ ] Telegram WebApp, админка и платежная страница открываются.

### SEO и контент

- [ ] У каждой индексируемой страницы правильный self-canonical.
- [ ] JSON-LD не содержит старого домена.
- [ ] `robots.txt` и `sitemap.xml` соответствуют домену запроса.
- [ ] `/app/`, `/api/`, `/uploads/`, `/admin` и оплата закрыты от индексации.
- [ ] Прямые URL `/site/*.html` не индексируются и, желательно, не публикуются.
- [ ] Все CTA и навигационные ссылки ведут на правильные домены.
- [ ] CSS, favicon и изображения загружаются без `404`, CORS и mixed-content ошибок.

### Полное удаление старого домена

- [ ] Поиск по репозиторию не находит `imagetransformation.ru`.
- [ ] Старый домен отсутствует в `.env` и документации развертывания.
- [ ] Старый домен отсутствует в Traefik и DNS.
- [ ] Старый email отсутствует в интерфейсе, письмах и юридических документах.
- [ ] Старый домен отсутствует в Telegram, ЮKassa, Метрике и кабинетах вебмастеров.

## 11. Критерии готовности

Миграция считается завершенной, когда:

1. Каждый из шести доменов обслуживает назначенную ему страницу или приложение.
2. Все CTA открывают `https://portret-iz-foto-ai.ru/app/`.
3. SPA, API, загрузки, email-подтверждение и оплата работают на основном домене.
4. У каждой индексируемой страницы правильный canonical и отдельный sitemap.
5. На тематических доменах недоступны API, админка и пользовательские загрузки.
6. В логах и аналитике определяется исходный домен лендинга.
7. Поиск по коду, HTML и конфигурации не находит `imagetransformation.ru`.
8. Старый домен полностью исключен из приложения и инфраструктуры.

## 12. Откат

Перед выкладкой сохранить тег или идентификатор предыдущего Docker-образа и резервную копию рабочих `.env`/Traefik-настроек.

Если после переключения обнаружена критическая ошибка:

1. Вернуть предыдущий образ приложения, сохранив новые DNS и домены.
2. Временно направить все новые домены на страницу технического обслуживания либо только на основной домен.
3. Не возвращать пользовательские ссылки на `imagetransformation.ru`, поскольку это противоречит целевой схеме.
4. После исправления повторить smoke-тесты и переключение внешних интеграций.
